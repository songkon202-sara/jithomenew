# JitHome — ขั้นตอนเปิดใช้ระบบความปลอดภัย (RLS)

ปิดช่องโหว่ระดับ CRITICAL จากรายงานตรวจระบบ:

- คนที่ไม่ได้ login อ่าน แก้ หรือลบข้อมูลผู้ป่วยได้ผ่าน Supabase REST API
- ผู้ใช้ทุกคนตั้งตัวเองเป็น admin ได้ (แก้ `role` ใน `user_profiles`)
- Telegram token ถูกส่งไปถึง browser และ Edge Function แจ้งเตือนไม่ตรวจการ login

> ⚠️ **ทำตามลำดับเท่านั้น** ถ้าข้ามขั้น ผู้ใช้อาจเข้าสู่ระบบหรือส่งแจ้งเตือนไม่ได้
> แนะนำให้ทำนอกเวลาใช้งาน และเตรียมบัญชีทดสอบทุกบทบาทไว้ (admin, เจ้าหน้าที่, อสม., ผู้สังเกตการณ์)

## ขั้นที่ 1 — เตรียมฐานข้อมูล (ไม่กระทบการใช้งาน)

Supabase Dashboard → **SQL Editor** → วางเนื้อหา `01_prepare.sql` → **Run**

ผลที่ควรเห็น: `ขั้นที่ 1 เสร็จ` และ `active_admins` มากกว่า 0

หลังขั้นนี้ ผู้ใช้จะตั้งตัวเองเป็น admin ไม่ได้อีก และผู้ที่สมัครเองด้วย Email จะอยู่ในสถานะ **รออนุมัติ** (เดิมเข้าใช้ได้ทันที)

## ขั้นที่ 2 — Deploy Edge Function (ชื่อ `bright-api`)

> โค้ดอยู่ใน `supabase/functions/notify/` แต่ deploy ใน Dashboard ด้วยชื่อ **`bright-api`** — แอปเรียกชื่อนี้ (`NOTIFY_FUNC_URL` ใน `docs/app.js`)

Supabase Dashboard → **Edge Functions** → **Deploy a new function** → **Via Editor**

1. ตั้งชื่อ `bright-api`
2. วางเนื้อหา `supabase/functions/notify/index.ts`
3. เปิด **Verify JWT** ไว้ (ค่าเริ่มต้น) → **Deploy**

หรือใช้ CLI: คัดลอกโฟลเดอร์ `notify` เป็น `bright-api` แล้ว `supabase functions deploy bright-api`

ถ้าใช้ `extract-medications` อยู่ ให้ deploy เวอร์ชันใหม่ด้วย (เพิ่มการตรวจ login)

## ขั้นที่ 3 — Merge โค้ดแอป

Merge PR นี้ แล้วรอ GitHub Pages อัปเดต (2–5 นาที) ผู้ใช้ต้องรีเฟรชแอป หรือปิดแล้วเปิดใหม่

ทดสอบ (ยังไม่ได้ล็อกฐานข้อมูล ทุกอย่างควรทำงานเหมือนเดิม):

- [ ] เข้าสู่ระบบได้ (admin ต้องกรอก 2FA)
- [ ] หน้าแอดมิน → LINE → **ทดสอบส่ง** ได้รับข้อความ
- [ ] หน้าแอดมิน → Telegram → **ทดสอบส่ง** ได้รับข้อความ (ทดสอบด้วยค่าที่ **บันทึกแล้ว**)
- [ ] หน้าแอดมิน → ส่งต่อ รพ. แม่ข่าย → **ทดสอบส่ง** ได้รับข้อความ

## ขั้นที่ 4 — ล็อกฐานข้อมูล

SQL Editor → วางเนื้อหา `02_lockdown.sql` → **Run**

ถ้าขึ้น error สคริปต์จะไม่เปลี่ยนแปลงอะไรเลย เพราะรันทั้งหมดใน transaction เดียว

ผลลัพธ์จะแสดงรายชื่อ **ตารางอื่นที่ยังไม่ได้เปิด RLS** ถ้ามี ให้ส่งรายชื่อมาตรวจเพิ่ม

### ทดสอบหลังล็อก

| บทบาท | สิ่งที่ต้องทำได้ |
|---|---|
| ไม่ได้ login | เห็นหน้า login, ชื่อหน่วยงาน, สมัคร อสม. ได้ |
| admin | ทุกอย่าง: ดู/เพิ่ม/แก้/ลบผู้ป่วย, ตั้งค่า, จัดการสมาชิก, ดู audit log, ปลดล็อกบัญชี |
| เจ้าหน้าที่ | ดู/เพิ่ม/แก้/ลบข้อมูลผู้ป่วยและนัด, บันทึกเยี่ยมบ้าน (ส่งแจ้งเตือน LINE) |
| อสม. | ดูผู้ป่วย, บันทึกเยี่ยมบ้าน, ส่งต่อ รพ. แม่ข่าย |
| ผู้สังเกตการณ์ | ดูหน้าภาพรวม |
| รออนุมัติ | เห็นหน้า "รอการอนุมัติ" เท่านั้น |

ตรวจจากภายนอกว่าล็อกสำเร็จ (ต้องได้ error `permission denied` หรือ `[]`):

```bash
curl "https://<project>.supabase.co/rest/v1/patients?select=id&limit=1" \
  -H "apikey: <anon key>" -H "Authorization: Bearer <anon key>"
```

## ถ้ามีปัญหา — ย้อนกลับ

SQL Editor → วางเนื้อหา `03_rollback.sql` → **Run**

ระบบจะคืนสิทธิ์และ policy เป็นแบบก่อนขั้นที่ 4 ภายในไม่กี่วินาที จากข้อมูลสำรองในตาราง `jh_security_backup`
หลังย้อนกลับ ข้อมูลจะกลับไปเปิดให้คนภายนอกเข้าถึงได้เหมือนเดิม จึงควรแก้ปัญหาแล้วรันขั้นที่ 4 ใหม่โดยเร็ว

## ขั้นที่ 5 — เก็บกวาด

- ลบ Edge Function เก่า **`smooth-endpoint`** ออกจาก Dashboard เพราะไม่ตรวจการ login และรับ token จากภายนอกได้
- ออก **Telegram Bot Token ใหม่** ผ่าน @BotFather (`/revoke`) แล้วบันทึกในหน้าแอดมิน เพราะ token เดิมเคยถูกส่งไปถึง browser

## ยังไม่ครอบคลุมในรอบนี้

- **Storage `patient-files`**: ถ้า bucket เป็น public ใครมี URL ก็เปิดรูปหรือไฟล์ผู้ป่วยได้ ควรเปลี่ยนเป็น private และใช้ signed URL
- **อสม. เห็นผู้ป่วยทุกหมู่บ้าน**: ยังไม่ได้จำกัดตามหมู่บ้านที่ระดับฐานข้อมูล
- **เลขบัตรประชาชน** ใน `patients` และ `user_profiles` ยังเก็บเป็นข้อความธรรมดา
- **RPC เดิมในฐานข้อมูล** (`record_failed_login`, `send_overdue_notification`) ไม่มีใน repo จึงยังไม่ได้ตรวจ
- ไฟล์ `app.js` และ `index.html` ที่ root ของ repo ดูเหมือนเป็นสำเนาเก่า (`docs/` มี manifest และ service worker ครบ จึงน่าจะเป็นตัวที่ใช้งานจริง) รอบนี้จึงแก้เฉพาะ `docs/` — ถ้า GitHub Pages ใช้ root อยู่ ต้องแจ้งก่อนรันขั้นที่ 4

## ขั้นที่ 6 — สิทธิ์ไฟล์ผู้ป่วย (Storage `patient-files`)

SQL Editor → วางเนื้อหา `04_storage.sql` → **Run** (หน้าต่างเตือน → **Run without RLS**)

- ปิดการอัปโหลดโดยคนที่ไม่ได้ login (policy เดิม `allow_upload_patient_files` เปิดให้ `public`)
- บัญชีที่รออนุมัติหรือถูกลบจะเปิดไฟล์ไม่ได้อีก แต่ผู้สมัคร อสม. ยังอัปโหลดสำเนาบัตรในโฟลเดอร์ `members/` ได้

ทดสอบ: admin เปิดรูปผู้ป่วยได้ · อสม. บันทึกเยี่ยมบ้านพร้อมรูปได้ · สมัคร อสม. ใหม่พร้อมแนบไฟล์ได้

ถ้ามีปัญหา → รัน `04_storage_rollback.sql`
